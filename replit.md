# Rhythmath

Open-source, in-house AI rhythm engine: generates, scores, edits, plays and exports percussion grooves from two traditions — Rio samba batucada and Arabic iqāʿāt — treating rhythm as mathematics (grammars + metrics + deterministic search), with no third-party AI services.

## Run & Operate

- `pnpm --filter @workspace/rhythmath run dev` — web app (workflow `artifacts/rhythmath: web`, preview path `/`)
- `pnpm --filter @workspace/api-server run dev` — API (workflow `artifacts/api-server: API Server`, mounted at `/api`)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm --filter @workspace/engine run test` — engine unit tests (vitest)
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from `lib/api-spec/openapi.yaml`
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`, `SESSION_SECRET`

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Engine: pure TypeScript (`lib/engine`), `@tonejs/midi` for SMF read/write
- Web: React + Vite + Tailwind + shadcn/ui, wouter routing, TanStack Query hooks generated by Orval, raw WebAudio (no Tone.js)
- API: Express 5, Replit Auth (OpenID Connect) sessions, multer uploads, App Storage for samples
- DB: PostgreSQL + Drizzle ORM; validation with Zod (`zod/v4`) via `@workspace/api-zod`

## Where things live

- `lib/engine/src` — the engine. `types.ts` (data model), `grammars.ts` (rhythm knowledge as data), `meter.ts`, `pattern.ts` (immutable editing), `metrics.ts`, `score.ts`, `generate.ts` (candidates → score → novelty re-rank), `spec.ts` (EN/PT/AR text parser), `midi.ts`, `analysis.ts` (in-house FFT / onsets / tempo), `synth-params.ts` (starter-kit voices)
- `lib/api-spec/openapi.yaml` — the API contract (source of truth for hooks + Zod)
- `lib/db/src/schema` — Drizzle tables (auth, projects, kits, samples, generations)
- `artifacts/rhythmath/src/audio` — browser audio layer (scheduler, synth, kits, decode); `src/lib/export.ts` MIDI/WAV download; `src/lib/license.ts` sample contributor licence
- `artifacts/api-server/src/routes` — one router per resource

## Architecture decisions

- Licensing split: engine/SDK Apache-2.0 (`lib/engine`), platform (web + API) AGPL-3.0. Keep SPDX headers on new files.
- Generation is deterministic given a seed; pattern ids are content hashes (`patternId`). Never use `Math.random` for musical decisions.
- Meters are data (`Meter`), never a hard-coded 16 steps; tempo is always quarter-note BPM; `pattern.swing` is a playback parameter, distinct from humanised `microOffset`s.
- Grammar templates are one-bar data marked `source: "standard reference, to be validated in alpha"` — musician validation is a planned alpha step, not done yet.
- Starter kits are synthesized at runtime from `SYNTH_PARAMS` and labelled as synthesized; real samples arrive through the uploader under the contributor licence.
- Score totals are 0..100 — do not multiply by 100 again in the UI.

## Product

- Compose: type a spec (English, Portuguese or Arabic) → ranked candidate grooves with explained scores → step-grid editing, mixer, transport, locked rows + regenerate, MIDI/WAV export, save to library (signed in).
- Analyze: drop an audio file → onsets, tempo, quantised pattern, closest grammars → send to Compose.
- Sounds: starter kits per tradition, custom kits with uploaded samples (licence acceptance required).
- Library: saved projects (duplicate / delete). About: the maths and the licences.

## Future Arabic research direction

- Treat Arabic iqāʿāt as cyclic cells: binary onset/rest structure plus qualitative voice labels such as dum and tak, rather than treating every pattern as only a Western bar.
- A later melody layer can model maqām as explicit microtonal interval vectors and sayr constraints; a later prosody layer can map ʿarūḍ units to rhythmic cells.
- These are research directions from the attached Arabic music notes, not claims that Phase 0 implements maqām, ʿarūḍ, or external research datasets. Any future implementation must remain in-house and separately validated with musicians.

## User preferences

- Fully open source and built in-house: no external AI/music APIs (no Suno etc.), no CDNs.
- Vocals are out of v1. UI must not mention "Replit". No emojis.
- Public repo: https://github.com/Banderalotebi/rhythmath (push after milestones).

## Gotchas

- After editing `openapi.yaml`, run codegen before touching routes or hooks.
- The web app is served at `/`; API calls must go through `/api/...` on the same origin (cookies for auth).
- Project/kit hooks must stay gated by `isAuthenticated`, otherwise the API returns 401 noise for visitors.
